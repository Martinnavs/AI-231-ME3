Topic D: keeping a USB sound card awake, ducking with an echo canceller, and hardware with on-board echo cancellation. Use ALSA / PipeWire / WirePlumber / Linux kernel documentation, Raspberry Pi forums and docs, vendor datasheets and product pages (Seeed Studio wiki, XMOS documentation, Jabra, Anker, Poly/HP), and independent measurements or reviews that contain numbers.

D1. A USB sound card on a Raspberry Pi (Debian/Raspberry Pi OS, user without sudo, the program writes directly to an ALSA hw/plughw device) delays the start of playback by about 0.5 s after it has been idle; keeping the ALSA PCM open and writing zeros continuously removes the delay without root. Some USB DACs auto-mute on digital silence, so +/-1 LSB dither is used instead of exact zeros. (Find sources for: why USB audio playback start can take hundreds of ms after idle; the effect of keeping the PCM open/streaming; USB autosuspend defaults (usbcore.autosuspend = 2 s) and whether an active isochronous stream prevents autosuspend; DAC zero-detect auto-mute.)
D2. WirePlumber suspends idle ALSA nodes after 5 s by default; session.suspend-timeout-seconds = 0 in a user config disables it. (Confirm the property name, default, and the config file syntax for WirePlumber 0.4 (Lua) and 0.5 (SPA-JSON).)
D3. With an echo canceller, ducking (turning the loudspeaker down when a user starts speaking) does not disturb the canceller if the reference is taken after the gain stage at the same sample position that goes to the loudspeaker; a mismatch in timing between the gain applied to the reference and to the loudspeaker disturbs the adaptive filter. Typical duck ramps are 50-100 ms down and 150-300 ms up. (Find primary sources: WebRTC/Android/AEC documentation or papers on where the AEC reference must be tapped relative to volume control, and any documented duck ramp times in voice assistants or telephony.)
D4. Seeed ReSpeaker USB Mic Array v2.0: XMOS XVF-3000, 4 microphones, on-board AEC, beamforming, noise suppression, direction of arrival; plug-and-play USB Audio Class 1.0 on Linux/Raspberry Pi; AEC only works when the loudspeaker is driven from the board's 3.5 mm jack (the board receives the playback); price about USD 69-79. (Confirm each part, the playback sample rate/channels it accepts over USB, whether it is still sold, and any published ERLE/echo figures or user reports of barge-in performance.)
D5. Seeed ReSpeaker Lite (XMOS XU316) and XMOS XVF3800-based kits (e.g. ReSpeaker XVF3800 USB 4-Mic Array): USB Audio Class plug-and-play on Linux with on-board AEC; the XVF3800 datasheet specifies AEC with a 150 ms tail length plus nonlinear residual echo suppression; price USD 35-99. (Confirm models, prices, AEC tail length and any published echo/ERLE numbers, and whether AEC works when audio is played to the device over USB.)
D6. USB speakerphones (Jabra Speak 510 / Speak2 40 / Speak2 55, Anker PowerConf S3 / S330, Poly Sync 20, eMeet M0/M2) work as standard USB audio devices on Linux and cancel echo of audio played through their own speaker in hardware. (For each: Linux compatibility evidence, whether AEC applies to audio played via the USB sound card interface, any independently measured echo return loss / double-talk performance, current price.)
D7. Any report (forum, blog, GitHub issue, paper) of barge-in or full-duplex voice-assistant performance with any of the devices in D4-D6 on a Raspberry Pi or Linux, e.g. Home Assistant voice satellites, Rhasspy, Wyoming satellite, OpenVoiceOS, Pipecat or LiveKit examples, with numbers (playback volume, false triggers, how often a user could interrupt).
