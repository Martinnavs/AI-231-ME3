Professor's requirements (ME3 briefing, 2026-10-15)

Recorded from the class briefing transcript; these override earlier assumptions where they conflict. - Generic full-duplex agent, English only: you can interrupt it mid-sentence and it stops and listens. Not half duplex. No wake word ideally (allowed only if the room is too noisy). - No model runs on the Pi except the VAD. The Pi runs the agent harness and the MCP servers, which reach models in the cloud (commercial APIs or the class DGX, which serves a Qwen model). → smart-turn dropped; end of turn comes from the cloud STT (tickets 05, 11). - ASR and TTS behind tools ("an additional tool for listening and one for speaking"); TTS must be interruptible (streaming, cancellable), not play-a-whole-file. → speech MCP server (06) + cancellable streaming TTS (05, 12). - The ten ME2 task groups must work for any phrasing and any value, including multi-turn clarification and mid-action corrections ("no, I want Opalite"). Groups: music, lights, temperature, weather, time, timer, alarm, call, message, reminders. → home narrowed to devices (07), media (19), assistant (20), task suite (18). - One random complex task at evaluation (e.g. "build a website"). → delegate + code subagent + publish_site (08). - Graded on correctness, latency/responsiveness and naturalness (warm, not bland; hard to tell from a person); research full-duplex benchmarks. → task suite (18), rig latency + barge-in + pause-takeover (13–15), warmer prompt (10), human naturalness rating (checkpoint 9). - Extend by adding MCP servers (e.g. a Spotify server) on a scalable harness; understand everything you build. docs/ reference files are written by the tickets that own each contract.

Search with rapidfuzz over "{artist} {title} {album} {genre}"; an artist-only match (query ≈ an artist name) returns that artist's tracks.
  2. Player: mpv as a separate process (--no-video --idle=yes --input-ipc-server=<runtime sock> --audio-device=alsa/<device>), controlled over its JSON IPC socket from asyncio. Started lazily on first play, restarted once if it died. FakePlayer implements the same protocol for tests and --fake. Effective volume = user volume × (duck factor when ducked); user volume persists across ducking.
  3. Tools (contract below). play always replaces what's playing (that's how a correction works). An artist query queues that artist's tracks, shuffled with a seed. No match above the score threshold → tool error listing up to 3 nearest titles, so the model can ask "did you mean…?".
  4. Ducking around speech (music_ducker.py): music must not drown out the user or the bot. On vad_speech_start (user) or bot speech start, call the hidden tool media__duck(on=True) (once; idempotent). When neither has spoken for media.restore_after_s (1.0 s), call duck(on=False). Emit MUSIC_DUCKED / MUSIC_RESTORED. No calls when the media server isn't configured or nothing is playing.
  5. One output device for everything. The bot (PortAudio) and mpv must play through the same speakerphone so its hardware echo canceller removes music as well as speech. Two processes can't open a raw hw/plughw ALSA device at once, so the runbook sets up an ALSA dmix (playback) + dsnoop (capture) pair for the speakerphone (deploy/asound.conf.example) and points both audio.output_device and media.audio_device at it. Preflight warns when media is enabled and the output device is a raw hw:/plughw: name.
  6. Docs: docs/MCP-SERVERS.md media section (tools, search rules, hidden duck); docs/PI-SETUP.md: sudo apt install mpv, filling ~/Music (any legally owned files; name them Artist - Title), the dmix/dsnoop setup and how to test it (aplay and mpv playing at the same time).

Action

ME2's base tasks include time, weather, timers, alarms and reminders, and the professor wants them to work for any phrasing and any value (2026-10-15). The ME2 dashboard only accepts a few preset values for these, so they live in our own server, which keeps their state on the Pi and tells the pipeline when something is due.

  1. Time: get_time(timezone=None) in AppConfig.timezone (zoneinfo).
  2. Weather: Open-Meteo (free, no API key): geocode the place name (default AppConfig.location), then fetch current conditions or the daily forecast for today/tomorrow. WebFetch the Open-Meteo forecast and geocoding API docs first; record the URLs and parameters in docs/MCP-SERVERS.md. Map WMO weather codes to plain words. 3 s timeout; cache per (place, when) for 10 minutes.
  3. Timers, alarms, reminders: stored in paths.state_dir/assistant.json (written atomically: temp file + rename). Free values: a timer of any duration from 1 s to 24 h, an alarm at any local time (today if still ahead, else tomorrow, unless a date is given), reminders with any text and an optional time. The model converts what the user said into these formats (ticket 10 prompt rule 5); tools validate strictly and return errors that say the expected format, so the model can fix the call itself.
  4. Due events: the hidden tool due_events() returns everything that fell due since the last call (timers done, alarms ringing, timed reminders), each delivered exactly once, and removes finished timers and one-shot alarms.
  5. Pipeline hook (assistant_events.py): poll assistant__due_events once a second. For each event, wait until the user isn't mid-turn (no VAD speech and no turn in progress; at most 10 s), then play a short chime (two-tone, 300 ms, generated in code) and speak a fixed template ("Your five minute timer for the eggs is done.", "It's seven fifteen. Here's your alarm.", "Reminder: call mom.") through the TTS directly — no LLM call, so it's instant. Then session.add_context_note(text) so the model knows what happened if the user responds ("snooze it", "thanks"). Emit ASSISTANT_EVENT. A barge-in stops the announcement like any bot speech.
  6. AgentSession.add_context_note(text): notes are added as a separate text block at the start of the next user message ([event] …), then cleared, never as a stray assistant message, so turn order stays valid.
