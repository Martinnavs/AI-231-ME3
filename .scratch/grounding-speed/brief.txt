OUR SYSTEM. A Python voice assistant (university research project, one user in Manila, Philippines, English). A spoken question that needs current facts ("Who is the current Senate President of the Philippines?", "gold price per ounce now", "who won the latest Ballon d'Or") is answered by ONE REST request to the Gemini API (AI Studio endpoint https://generativelanguage.googleapis.com/v1beta/models/gemini-3.1-flash-lite:generateContent, API key header) with tools [{"google_search": {}}], generationConfig.thinkingConfig.thinkingLevel = "minimal", a short system instruction (today's date; answer in at most two short sentences, plain words, spoken aloud; search whenever the answer could have changed; do not search for settled facts). The text is spoken by local TTS. We already: keep the HTTPS connection warm (httpx keep-alive plus a periodic GET to the API while the agent is in use), use IPv4, cache identical questions 10 minutes, fall back to Tavily after 3.0 s. A separate small local router decides the turn needs the web (0.13 s), so the grounded call is the whole remaining cost.

MEASURED (Manila, 2026-11-03, warm connection): grounded call median 1.98 s over 40 search-needed questions (2.10 s when it searched, 1.27 s when it did not), 33/40 correct, 33 searches; median 0.79 s on a mixed set of 25. Streaming (streamGenerateContent?alt=sse) on a few searched questions: first text 1.39-1.44 s, end 1.63-1.87 s. Tavily (fast + answer) 1.25 s, less accurate on changing facts. End-to-end the spoken answer starts about 3.4 s after the user stops talking; everything else is about 1.1 s (speech-to-text 0.92 s, TTS 0.21 s). Goal: cut the grounded call's time to first spoken words without losing accuracy (it must search for changing facts; answering from memory gave stale or invented answers).

ALREADY TRIED, DO NOT REPEAT: putting google_search in the main agent request next to 8 function tools (needs toolConfig.includeServerSideToolInvocations; the model then rarely searched); free search APIs as replacements (none beat Tavily); OpenRouter search (3.4-5.0 s).
