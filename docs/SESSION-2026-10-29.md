## Decisions and the evidence behind them

**1. The router is the 350M fine-tune, not the H-1B.** Same Q4_K_M, 8 threads, one server at a time, greedy, one run each.

| Router | OnIt (77 turns) | Pack (92 turns) | Call p50 / p95 |
|---|---|---|---|
| H-1B v1 (was hosted) | 69/77 | 80/92 | 0.34 / 0.59 s |
| 350M v1-s0 | 74/77 | 75/92 | 0.11 / 0.14 s |
| **350M kd-s0** | **76/77** | 79/92 | 0.11 / 0.15 s |

Live, the router call takes 0.16-0.26 s (the H-1B took 0.6-1.0 s because it shares four cores with the speech server). The adapters are LoRA on `ibm-granite/granite-4.0-h-350m`; `~/work/gguf-tools/convert.sh <repo> <name>` merges and converts them (`BASE=` overrides the base model; the default is the H-1B).

**2. The router must not use 8 threads.** With three of the four cores busy, the 8-thread router timed out on every request; it did the same through a whole stress run, so Gemini answered everything (3-6 s). Idle it takes 35-50 ms at any count (n=12-15 per setting). Measured under load: 8 threads timed out, 4 threads 55 ms median with one 2.5 s stall, **3 threads 54 ms**, 2 threads 65 ms. Serve it with `-t 3 -tb 3`.

**3. The voice is Kitten Micro Jasper.** UTMOS put Supertonic F1 at 5 steps (4.35) level with Kitten Micro (4.26-4.29), but a blind A/B listening test (30 trials, one listener, laptop speakers) chose Kitten in **20 of 20** cross-family comparisons. UTMOS did not predict it, and the fifth Supertonic step was not audible, so do not choose a voice by UTMOS alone. Jasper and Luna were indistinguishable (3:2); Jasper is faster (225 ms against 251 ms for short chunks). Parakeet word error and name recognition were a tie with the old voice. Work and clips: `~/work/tts-bakeoff` (**do not delete until the production version is agreed**; so also `~/work/gguf-tools`).

- Kitten's own cleaner lowercases everything, drops commas and periods, turns "person's" into "person s" ("person ess"), "AM" into the word "am" and "1933" into "one thousand nine hundred thirty-three". `kitten_text` keeps case, apostrophes and punctuation, spells AM/PM as letters and says years as years.
- `kittentts` is not a project dependency. Set `KITTEN_SITE` to a site-packages directory that holds it (the bake-off environment); the engine appends it to `sys.path`. Its wheel's metadata does not match its filename, so it was unpacked by hand.
- The client always sends its own voice name (Supertonic's `F1`); the Kitten engine falls back to Jasper for any name it does not know.
- **Level.** Raw Kitten is 4.4 dB louder than the original voice (-16.9 against -21.3 dBFS active RMS, peaks near 0 dBFS), which pushed the echo gate's playback level from 0.097 to 0.16-0.17 and its bar up with it. `match_level` brings every chunk to -21.3 dBFS (gain limited to -9/+3 dB, peak 0.95), so the existing echo tuning applies. Through the engine, 39 real sentences sit at -20.9 dBFS with a 0.06 dB spread.

**4. Web answers come from Tavily; Wikipedia is the fallback.** `web_answer(query)` posts to `https://api.tavily.com/search` (`include_answer: basic`, 3 results, depth `fast`), says the first two sentences (at most 400 characters) and drops "According to the provided source,". It falls back to Wikipedia (`web_info.wiki_text`) when there is no key, an error, a timeout (3.5 s in all) or no answer.

- **Key:** `$TAVILY_API_KEY`, else `~/.secrets/tavily/api-key.txt`. **Hard rule: never read or print it.** The code reads it at run time and sends it only as the `Authorization` header. The question text goes to Tavily.
- **Router:** it still writes `wiki_summary|topic` (that is what it was trained on); the agent server runs it as `web_answer` with the user's whole question (the topic alone when the turn did other things). No retraining. Gemini sees `web_answer` and the system prompt prefers it; `wiki_summary` stays registered.
- **Latency.** Fresh queries from Manila, 4 each: `basic` 2.35 s, `fast` 1.21 s, `ultra-fast` 1.24 s. The network floor is 0.25 s round trip to a US East address. Two real findings: httpx closes idle connections after **5 s** by default, so every lookup paid TCP, TLS and the first byte (0.5-0.9 s); and Tavily's server appears to drop an idle connection between 15 and 45 s (one sample each: a kept-alive call after 45 s idle took 3.49 s). So the client keeps connections 120 s, a free `GET` on the API root goes out every 20 s while the server is in use (no search is run), the connection is opened at start, and answers are cached 10 minutes (64 entries, keyed on the question without case or punctuation). A lookup after a 15 s pause: 1.93 s median before (n=4), 1.32 s with the long keep-alive alone; with the pings 1.06-1.68 s at 15, 45 and 90 s of idle (one call each). A cached repeat: 6 ms. The weather and Wikipedia client got the same 120 s keep-alive.
- **OpenRouter was evaluated and not used.** Its web search is a server tool the model calls inside a chat request (`openrouter:web_search`, the `:online` suffix, Responses-API search); there is no standalone search endpoint. With `gemini-3.1-flash-lite` and 4 questions each it took 3.44 s (Perplexity search), 4.91 s (Parallel turbo) and 5.01 s (Exa instant), against 1.14 s for the model alone and about 1.1-1.7 s for Tavily.
- **Not built:** speculative prefetch (start the Tavily search from the router's escalation while Gemini is still deciding on the tool call, about 1 s on Gemini web turns).

**5. The echo guard has a minimum bar.** The bar is `max(4 x room noise, expected echo)`. In a quiet room (-40 dBFS, against -35 on the baseline day) the first term falls to 0.040, on the echo's own 95th percentile (0.033-0.042), and one echo-only clip of six fired the guard. `--barge-min-bar 0.06` (-24 dBFS; speech at the microphone is about -17 dBFS) is an absolute floor, off by default. Replayed offline on every recording: today's run 1/6 false -> 0/6 false with 6/6 hits (median 0.40 s); the older, noisier recordings are unchanged (2/18 false, 9/12 hits, both before and after). It was chosen after seeing that recording, so it is not held out; the final stress run is the first live check (below).

**6. Router robustness fixes** (`pipeline/src/voice_pipeline/router.py`, `agent_server.py`): a failed read-only lookup is retried once when the failure looks transient (not for "couldn't find"); an extra `|` field on a home command is folded into its single slot (`ALARM|6:30 AM|tomorrow` -> "6:30 AM tomorrow"); a `none|` reply that repeats a user turn of three or more words is handed to Gemini.

## How to bring it up

```
# router (3 threads)
LD_LIBRARY_PATH=~/work/gguf-tools/llama.cpp/build/bin ~/work/gguf-tools/llama.cpp/build/bin/llama-server --jinja -c 8192 -np 1 -fa on -t 3 -tb 3 -m ~/work/gguf-tools/models/router-350m-kd-s0/gguf/router-Q4_K_M.gguf --port 8089
# Pi speaker and device tools: see HANDOFF.md section 9 (they stop themselves after 2 h)
# speech server, Kitten voice
LAN_SPEECH_TOKEN=$(cat ~/.config/lan_speech_token) KITTEN_SITE=~/work/tts-bakeoff/venv/lib/python3.12/site-packages \
  uv run --offline --group laptop python -W ignore -m lan_speech --host <cable ip> --port 8770 --stt-model parakeet \
  --entities config/entities.json --tts-engine kitten --kitten-voice Jasper
# agent server
cd pipeline && LAN_SPEECH_TOKEN=... uv run python -m voice_pipeline.agent_server --router-url http://127.0.0.1:8089 --ipv4
# the live loop: .scratch/router-voice/run.sh (--fillers --barge-min-bar 0.06 --aec --duck-db -15 ...)
```

## Open

- **Router answers a date question with the time** ("What's the day's date?" -> "It's 2:08 PM."): the router has no date tool.
- **Router parrots near-copies of garbled turns** ("Pucket on Muyoung Hilo" -> "Pucket on Muyong Hilo"): the guard needs a fuzzy match.
- **`web_answer` can answer about the wrong year** ("2087 Nobel Prize" -> the 1987 laureates). It is a spoken-result tool, so Gemini never checks it. A future-year guard and a year-mismatch check are the fix.
- **"I'm feeling cold" sets the thermostat to 24 degrees** (Gemini, after the router's chat reply is rejected as too long).
- **The router invents trivia replies** (the phonebook line, a joke); only the length rule catches them.
- **A weather follow-up that needs reasoning** ("should I bring an umbrella?") repeats the forecast.
- **Hedged Gemini requests each call Tavily**, so a turn can spend two searches.
- **The first weather lookup of a new place** can take 4-11 s (weather needs its own keep-alive measurement).
- **Not listened to:** AM/PM, years, apostrophes, "EDSA" and seams after the text fix and level matching.
