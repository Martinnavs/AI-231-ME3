# Context management for refinement dialogues: research and a lean plan (2026-11-12)

What this is: five search-only agy runs (axes: working memory, reference resolution, editing a deliverable the front agent cannot see, voice-specific problems and testing, prior-art architectures), the owner's session of 2026-11-12 08:39 as the case, and our code. Raw reports and the briefs are in `.scratch/context-research/` (git-ignored). Agy claims were spot-checked against the primary pages (Pipecat Flows `ContextStrategy`, Anthropic's "effective context engineering" page, Manus's context-engineering post: all say what the reports quote); the rest is cited as agy's and weaker.

## The case (what failed)
Five cities were researched and a page built. Then "the other two cities" and "their order" could not be resolved (the front agent never sees the page; the weather tool had failed for two cities and the page said "not available"); the agent re-searched instead of acting for three turns, drew Cebu from an unrelated weather question ten minutes earlier, and the final update rebuilt the page with a new three-city set (Manila, Caloocan, Taguig lost). A split request and a cut sentence were acted on as complete.

## Evidence strength and caveats

## Built (2026-11-12, later): ideas 1, 2, 3, 4, 5, 6 and 9, as one generic mechanism
The task is a **working set** (items), a **deliverable manifest** (what it holds and lacks) and the **corrections**; four rules act on them: resolve references against the set, route a refinement as an update, update with "keep all of these", verify afterwards.
- `chain_state.py`: `items` (added to, never replaced; `remove` drops; at most 12), `gaps` (replaced), shown in the [ACTIVE TASK] and [ARTIFACT] lines; a refinement ("update", "add", "the other two", "table", "order", ...) counts as a follow-up, so a finished task no longer ends when the user refines it (that wiped the state in the live session).
- `chain_update(items=, remove=)` tool arguments; the delegate boundary adds, to any refinement of a finished deliverable, "Update the existing <file> in place ... Keep ALL of these items: ... It is known to lack: ..." and, for page, table or list tasks, the ask to write `MANIFEST.json`.
- Sub-agent (`subagent.py`): writes `MANIFEST.json` beside the file (items, gaps); an update task that names items to keep is checked against the page after the run: lost items are sent back once, and named in the summary ("Not kept: ...") if still missing. After a job, `note_chain_job` reads the manifest (plain small file inside the workspace only) into the chain.
- Case F prompt block: refine means delegate the change, no search, "the other two" means the items or the missing entries, "No, I mean ..." redoes the last action; the base prompt says a compound "X, and then make a page" is never answered with only X.
- `weather` and `nearby` retry the geocoder without "City", "Municipality", "Town" or "City of" (Open-Meteo knows "Caloocan" and "Taguig", not "Caloocan City" and "Taguig City").
- Evals: scenario `refine_keeps_items` (build a list page, "make it a table and sort it", "add a title and a note"), four unrelated subjects (Philippine cities, smartphones, Cebu festivals, Jupiter's moons), generic checks `items_kept`, `no_lookup_on_refinement`, `refinement_is_patch`. First run (before the manifest ask went into the task text): 3 of 4 domains passed; the smartphones run answered only the first half of "name X and then make a page" and the sub-agent wrote no manifest. After both fixes: **6 of 6** (cities x2, phones x2, festivals, moons). Live spend for this feature about $0.22 in total (more than the $0.10 estimated). Regressions run live: `their_means_the_latest_list`, `followup_while_running`, `about_me_page` all pass. Tests: pipeline 721, root 1,313 (the documented `test_flow` deselected).
- Not built: ideas 7 (split utterances: the existing `--ask-to-add` stays off) and 8 (the state block is already at the tail). Known weak spot: the working set is filled by the model's `chain_update` or the sub-agent's manifest; when neither happens the check has nothing to compare (the eval counts that as a failure).
